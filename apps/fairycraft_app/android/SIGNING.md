# Android Signing Configuration Guide

## Overview
This guide documents how signing is configured for FairyCraft app flavors (dev/prod) and build types (debug/release).

## keystore.properties (Sensitive)

File: `android/keystore.properties` (git-ignored by default)

Template:
```properties
storeFile=C:\\src\\Secrets\\release.jks
storePassword=Pulsar_1984
keyAlias=releaseKey
keyPassword=Pulsar_1984
```

**Important:**
- Replace placeholders with actual keystore passwords.
- This file is **git-ignored** and should NOT be committed.
- Keep it secure; restrict file permissions to authorized users only.

## Signing Configuration

### Flavors
- **dev**: Android App ID = `com.fairycraft.app.dev` (via applicationIdSuffix = ".dev")
- **prod**: Android App ID = `com.fairycraft.app` (unchanged)

### Build Types
- **Debug**: Uses debug keystore (auto-generated by Android SDK, no credentials needed)
- **Release**: Uses release keystore (loaded from `android/keystore.properties`)

### Resulting Variants
```
devDebug        (dev app, debug keystore)
devRelease      (dev app, release keystore)
prodDebug       (prod app, debug keystore)
prodRelease     (prod app, release keystore)
```

## Getting SHA-1 / SHA-256 Fingerprints

### Command
Run from `apps/fairycraft_app/android/`:
```bash
./gradlew signingReport
```

Or on Windows PowerShell:
```powershell
.\gradlew signingReport
```

### Filtered Output (Windows PowerShell)
```powershell
.\gradlew signingReport | Select-String -Pattern 'Variant:|SHA1:|SHA-256:'
```

### Expected Output (once keystore.properties is populated)
```
Variant: devDebug
SHA1: XX:XX:XX:...:XX
SHA-256: YY:YY:YY:...:YY

Variant: devRelease
SHA1: AA:AA:AA:...:AA
SHA-256: BB:BB:BB:...:BB

Variant: prodDebug
SHA1: XX:XX:XX:...:XX
SHA-256: YY:YY:YY:...:YY

Variant: prodRelease
SHA1: CC:CC:CC:...:CC
SHA-256: DD:DD:DD:...:DD
```

**Note:**
- Debug variants (devDebug, prodDebug) will show the same SHA-1/SHA-256 (debug keystore is shared).
- Release variants (devRelease, prodRelease) will show different SHA-1/SHA-256 once the release keystore password is set.

```bash
flutter build apk --flavor prod -t lib/main.dart --dart-define=FLAVOR=prod --release
```

## Firebase & App Registration

### Dev Variant
- **Android App ID**: `com.fairycraft.app.dev`
- **Firebase Project**: `fairycraft-dev`
- **google-services.json**: `android/app/src/dev/google-services.json`
- **Firebase Options (Dart)**: `lib/firebase/firebase_options_dev.dart` (selected via `--dart-define=FLAVOR=dev`)

### Prod Variant
- **Android App ID**: `com.fairycraft.app`
- **Firebase Project**: `fairycraft-prod`
- **google-services.json**: `android/app/src/prod/google-services.json`
- **Firebase Options (Dart)**: `lib/firebase/firebase_options_prod.dart` (selected via `--dart-define=FLAVOR=prod`)

## Keystore Lifecycle

1. **Creation** (one-time):
   ```bash
   keytool -genkeypair -alias releaseKey -keyalg RSA -keysize 2048 \
     -keystore C:\Secrets\release.jks -validity 3650
   ```
   (Already done; saved to `C:\src\Secrets\release.jks`)

2. **Populate `keystore.properties`** (one-time after keystore creation):
   - Add actual passwords (from secure location / password manager).
   - Ensure file is in .gitignore (already configured).

3. **Build & Sign**:
   - Release builds automatically use the release keystore via Gradle.
   - Gradle loads passwords from `keystore.properties` at build time.

## Troubleshooting

### Release signing fails with "keystore.properties not found"
- Ensure `android/keystore.properties` exists.
- Check file path and format match the example above.

### Release signing fails with "invalid password"
- Verify passwords in `keystore.properties` are correct.
- Regenerate the keystore if passwords are lost.

### Debug variants show no SHA-256
- This is normal; debug build types don't always display SHA-256 in signingReport.
- Debug SHA-1/SHA-256 are only needed for local development; they're not used for Firebase registration.

### Release SHA-256 is missing in signingReport
- Ensure `keystore.properties` contains real (non-placeholder) passwords.
- Run `./gradlew clean` and retry `./gradlew signingReport`.

## Git & Security

- **DO NOT commit**: `android/keystore.properties`, keystores, or any files containing credentials.
- **DO commit**: `.gitignore` rules (already configured to exclude `**/keystore.properties`).
- **Safe distribution**: Use secure secret management (e.g., GitHub Secrets for CI/CD, encrypted password manager for dev).
